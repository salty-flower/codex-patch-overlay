## Port

Scheduled auto-release failed from 2026-10-15 onward:
it targeted `rust-v0.163.0` → `tui-notification-sound` no longer applied at `codex-rs/tui/src/tui.rs`,
which stopped the run before the later patches were checked.
Rebuilding the old stack on `rust-v0.162.1` and rebasing it onto `rust-v0.163.0` gave a real three-way merge for every patch.
Nine patches keep their added and removed lines unchanged;
`websocket-reconnect` is among them but needed its conflict resolved by hand.
`tui-notification-sound`, `editable-enter-queue`, and `codex-rotate` changed content.

`tui-notification-sound` passes the default sound config in upstream's new `/config` panel test.
The patch adds a sound parameter to `Tui::set_notification_settings`;
the test file is new in 0.163.0, so the patch applied cleanly and only the compile failed.
The test uses the `Bel` backend, which never plays a sound.

`editable-enter-queue` follows upstream's rewrite of the Daybreak routing test into a loop over feature combinations;
each submission still generates its own client message ID.

`websocket-reconnect` moves its blackholed-reuse test above the `test_case` attributes
that upstream added to `responses_websocket_creates_on_non_prefix`.

`codex-rotate` follows upstream's extraction of HTTP streaming into `ResponsesHttpExecutor`,
which borrows the client and no longer owns the turn session.
The executor carries the step's pinned rotate auth and residency.
The session passes a callback, so every retry still adopts the request identity
and gets fresh routing state when that identity changes, including a new credential revision.
Upstream's new background compaction built its HTTP request from the shared model client;
it now pins the step's admitted account and captured HTTP policy, as foreground compaction does,
and its own callback drops the replayed foreground routing token when the identity changes,
without touching foreground state.
The zsh-fork test hunk is dropped with the test file upstream deleted.

Upstream #52160 removed the zsh-fork shell backend, its `codex-zsh` DotSlash manifest, and `zsh.py`,
and now ignores `shell_zsh_fork`.
The release workflow, Nix overlay, flake checks, and docs no longer ship `codex-resources/zsh/bin/zsh`;
the package still creates the `codex-resources` directory that upstream's layout validator requires.

Upstream added code-mode host tests that spawn the real `codex-code-mode-host` binary,
so the CI unit-test job builds it alongside `test_stdio_server`.

The stable and experimental compressed app-server exports are regenerated from the cumulative patched source,
because upstream changed its own exports in 0.163.0.
The schema refresh workflow now runs on the branch it is dispatched from, so a port branch can regenerate them before merge.

`rusty_v8` stays at 150.4.0.
