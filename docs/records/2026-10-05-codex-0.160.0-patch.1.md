# codex-0.160.0-patch.1

## Source

- Upstream: `openai/codex@rust-v0.160.0`
- Upstream SHA: `a956835d020762cb2b570053af06f643a11c0ecc`
- Patch release: `codex-0.160.0-patch.1`

## Port

All 13 enabled patches remain carried in manifest order.
Scheduled auto-release failed from 2026-10-02 onward because `timed-queue` no longer applied by plain `git apply`;
it and the patches before `editable-enter-queue` rebase cleanly with a three-way merge.
Upstream #49105 adds reconnect delivery tracking:
queued messages carry `MessageDelivery`, and thread input state carries `reconnect_pending` and the pending client message ID.
`editable-enter-queue` keeps those fields next to its `edit_order` and `next_edit_order`.
When restoring pending steers, it still skips claimed steers and still orders retries by edit order,
and each restored steer now takes upstream's delivery state (`Unconfirmed` with its client ID after a reconnect, otherwise `Unsent`).
The remaining patches rebase on context only.
Upstream did not change `app-server-protocol` in this release, so the carried schema exports regenerate byte-identical.

Two defects carried over from earlier ports are fixed here.
`editable-enter-queue` adds a `Submission` initializer, but its `residency_guard: None` field was carried in `codex-rotate`,
so the stack cut after `editable-enter-queue` did not compile; the field now lives in `editable-enter-queue`.
`websocket-reconnect` probes a pooled Responses socket before reuse.
Seven realtime conversation tests share one fixture server and script the Responses connection with no requests,
so the fixture never reads that socket again → the probe gets no Pong → the client opens a new socket for the warm-up
→ that new socket takes the connection slot the test scripted for the realtime session.
Those fixtures now answer the warm-up on the Responses connection.

Rust 1.99.0 became the stable release CI installs on 2026-10-01.
Its Unicode tables no longer make `Debug` escape halfwidth sound marks,
so the request-user-input truncation snapshot printed `ｶﾞ` where the committed snapshot expected `ｶ\u{ff9e}`.
`rust-toolchain-stable` opts into the stable channel, so it now carries the 1.99 form of that snapshot.
Local Rust 1.98.1 test runs fail that one snapshot until the local toolchain reaches 1.99.

`scripts/refresh-editable-enter-schema.nu` now passes an absolute schema root.
With the relative default, `cargo test` resolved it from the crate directory,
wrote the regenerated exports into a nested `staging/` tree,
and the script then copied upstream's unpatched exports into `patches/`.

## Verification

The complete enabled stack passes cumulative `git apply` and `patch -p2` application on a fresh upstream checkout,
and the resulting tree matches the tested staging tree exactly.
Manifest and editable-queue checks pass.
`cargo check --tests` passes for the TUI, core, app-server, app-server protocol, and protocol crates,
and for the stack cut after `editable-enter-queue`.

Tests ran on Linux inside a sandbox, through nextest with upstream's `just test` settings
(`RUST_MIN_STACK=8388608`, `NEXTEST_PROFILE=local`) and with `CODEX_SQLITE_HOME` and `NO_COLOR` unset.
Across 13 affected crates, 14,013 of 14,649 tests passed, with 20 skipped.
The same run on upstream `rust-v0.160.0` plus only `chatgpt-recursion-limit`, which upstream needs to compile here,
failed 626 tests plus 2 timeouts.
Every failure there also fails on the patched tree.
Most come from the sandbox:
nested `bwrap` namespaces fail with `ENOSPC`,
and snapshots recorded on upstream `main` expect version `0.0.0`, while release tags set the real version.
Eight failures appeared only on the patched tree.
Seven were the realtime fixture conflict above; all 89 realtime conversation tests pass after the fixture fix.
The eighth, `connector_requests_preserve_account_policy`, passed in the full baseline run,
but it fails 3 out of 3 times in isolation on the same baseline tree, so it is unstable upstream rather than a patch regression.
All 16 halfwidth sound-mark TUI tests pass under Rust 1.99.0 with the updated snapshot.
Without upstream's stack setting, an earlier run aborted thousands of tests with stack overflows; that run is not counted.

Upstream warnings remain for unused imports in `core/src/tools/registry.rs` and `core/tests/suite/scenarios.rs`,
and future Rust incompatibility in `proc-macro-error2` 2.0.1.
`nu scripts/check-release.nu` passes, including `nix flake check --all-systems` and the package-layout check.
The x86_64-linux Nix package builds and reports `codex-cli 0.160.0`.
macOS binaries and an interactive manual TUI check were not run on this Linux host.
No release tag or publication is created by this upgrade commit.
