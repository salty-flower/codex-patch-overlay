## Toolchain and local environment

CI uses the stable Rust channel and updated build actions.
The release workflow now installs the latest stable Zig directly from its official download index and verifies the archive SHA-256.
This replaces the Zig setup action, whose latest release still declares the deprecated Node 20 runtime.
The flake lock includes the maintainer's nixpkgs update.
Nixpkgs 26.11 no longer supports Intel macOS, so the flake exports only Apple Silicon macOS and both Linux architectures.
Local builds use eight Cargo jobs, with one build running at a time.
Unit tests run with two concurrent cases; integration scenarios run serially.
Linux CI re-enables the historical test exclusions for verification on this baseline and toolchain.

The inherited Nix linker failed a standalone Rust panic-unwind probe.
Local tests use Apple's compiler, SDK, and classic linker; the standalone panic probe passes with this combination.
The same panic probe also passes inside the current flake's clean Nix C/Rust build environment.
The classic linker also avoids the newer Apple linker's compact-unwind size warning for large debug test executables.
Tests unset the runner's `CODEX_SQLITE_HOME` override so configuration fixtures use their temporary homes.
Color snapshot tests also unset the runner's `NO_COLOR` override.
Unsandboxed test commands unset inherited `CODEX_SANDBOX` and `CODEX_SANDBOX_NETWORK_DISABLED` markers so upstream network and process tests execute their assertions instead of returning early.
CI launches `cargo-nextest nextest` directly with `CODEX_CA_CERTIFICATE` and `SSL_CERT_FILE` unset for unit tests.
The native TLS fallback fixtures require the platform's default backend; Cargo's Linux OpenSSL initialization can otherwise inject a certificate path and make Codex select rustls before the fixture runs.
Custom-CA tests continue to supply their own explicit environment.

The maintainer waived only the known `proc-macro-error2 2.0.1` future-compatibility warning for these releases.
