## Why patch.2

Two upstream changes broke `tui-status-line-command` without breaking its patch application.

Upstream 0.156 added the owned fullscreen transcript, which is on by default with the alternate screen.
It reserves a separate row for the built-in status line.
The patch only replaced the built-in line inside the hint row, so both lines showed.
Removing `tui.status_line` did not help: upstream falls back to its default items, and the patch enables the status line while command output exists.

Upstream 0.157 added the `⚠ N warnings` notice to the passive footer.
While it shows, upstream collapses the hint area to one row and narrows it to end before the notice.
A two-row command output lost its second row, and the first row lost its right-aligned segments.

The patch now:

- suppresses the separate built-in row while command output exists;
- keeps the command rows' height while the notice shows, so the notice shares the last row;
- renders command rows at the full footer width and clips only the row shared with the notice;
- adds `warnings.count`, `warnings.shortcut`, and `warnings.reserved_columns` to the stdin snapshot, without a schema version bump.

The first CI run caught the one-row collapse through the new composer regression test; nothing was compiled locally.
The field comment for `reserved_columns` omitted the 2-column row indent; the README states the width rule, and [PR #10](https://github.com/salty-flower/codex-patch-overlay/pull/10) corrects the comment for the next release.
