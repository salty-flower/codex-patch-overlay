## Change

Scrolling the transcript with the mouse wheel in Ghostty on macOS sometimes interrupted the running turn
and inserted fragments such as `[<65;113;25M[<65;112;26M` into the composer.
The same symptom is reported upstream in openai/codex#52519 (0.162.0) and #49184 (0.157.1, closed as fixed in 0.159.0).

When a terminal read ends right after the `ESC` of an SGR mouse report,
crossterm's Unix event source emits the Escape key at once → Escape interrupts the turn →
the next read delivers the rest of the report as typed text.
crossterm already holds a lone `ESC` for a 20 ms ambiguity window, but only for input buffered at startup.
The new `crossterm-split-escape` dependency patch makes the regular read path use the same window.
A real Escape press still arrives after the window.

crossterm is pinned by git revision at `openai-oss-forks/crossterm@ed1cdab`,
so this release adds `[[dependency_patches]]`:
patches applied to a locked dependency's source, pinned to its exact `Cargo.lock` source string.
Nix patches the vendored copy in `postPatch`;
CI and release builds run `scripts/ci/apply-dependency-patches.py` and discard Cargo's cached build of the crate.

The twelve codex-rs patches are unchanged from `codex-0.163.0-patch.1`.

## Verification

- In crossterm, the two new event-source tests fail on the unpatched source, which emits Esc for a lone trailing `ESC`, and pass with the patch.
  The other 20 tests in that module pass; one existing paste-timeout test is intermittent with or without the patch.
- The patch applies to the Nix-vendored crossterm, and the rendered `postPatch` step fails when `Cargo.lock` pins a different revision.
- On a 0.163.0 workspace the CI script applies the patch, recognizes a second run as already applied, and fails on a moved lock.
- CI `check` runs `nix flake check --all-systems` and the unit and integration test sweep with the dependency patch applied.
