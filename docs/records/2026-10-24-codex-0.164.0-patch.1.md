## Port

Scheduled auto-release failed from 2026-10-19 onward, for two reasons in sequence.
From 2026-10-19 to 2026-10-23, `RELEASE_PUSH_TOKEN` no longer authenticated →
the checkout step failed with `could not read Username` before any upstream release was considered.
After the token was replaced on 2026-10-24, the rerun targeted `rust-v0.164.0` →
`plan-mode-default` no longer applied at `codex-rs/core/config.schema.json`,
which stopped the run before the later patches were checked.
Applied cumulatively, eight of the twelve patches failed `git apply --check` on `rust-v0.164.0`.
Rebuilding the stack on `rust-v0.163.0` and rebasing it onto `rust-v0.164.0` left conflicts in six patches.
Of the other six, five keep their added and removed lines unchanged; `core-test-unused-import` loses one hunk, described below.

`timed-queue` lists `/later` next to the commands upstream now allows inline arguments for (`/model`, `/permissions`, `/title`, `/statusline`).

`editable-enter-queue` follows upstream's new `has_pending_injection` flag on the turn input queue (#55644).
The patch's `try_extend` sets the flag only for notifying injections, as upstream does, and `take_all` clears it.
Clearing pending input now takes the items with the steer bookkeeping and drops them after releasing the turn-state lock,
because upstream's pending mail can own attachments whose destructors need that lock.
The recall submission fills upstream's new `message_delivery` field.

`websocket-reconnect` keeps skipping non-request frames before a scripted response is consumed,
inside upstream's new loop that ignores a late `response.interrupt` and gates scripted events.
The blackholed-recovery fixture fills upstream's new `response_gates` field.

`codex-rotate` follows three upstream refactors:
- App-server logout moved into the shared `logout_configured_account`, which upstream's new startup configuration recovery (#55300) also calls.
  The helper-aware logout now lives there, so both paths clear the helper-owned selection instead of revoking native auth.
- Step capture now reads settings and environments under the active-turn lock and then the state lock,
  and also captures the inherited environment snapshot for spawned threads.
  The rotate pre-capture before account admission does the same and passes the inherited snapshot through.
  The rotate MCP barrier runs after upstream's new cloud-catalog refresh, so the gate is still held through binding capture.
- Login now records OAuth provenance and passes the exchanged token set to `persist_tokens_async`.
  Helper enrollment reads the same token set; refresh keeps its rotate guard ahead of upstream's provenance-aware refresh request,
  and proactive refresh still returns no reason for a rotate account.
The rotate request snapshot fills the new `oauth_provenance` and `login_owner_id` with `None`, as upstream does for externally supplied tokens,
and the scoped request manager wraps its refresh lock in the `Arc` upstream now uses.
The rotate step wrapper pushes step-capture futures past the default trait-evaluation depth,
so `codex-core` raises its recursion limit to 256, as upstream already does for `codex-tui`, `codex-app-server`, and `codex-chatgpt`.
The MCP refresh round tests move into upstream's new `mcp_refresh_tests.rs`;
the rotate tests follow the renamed `proactive_refresh_reason`, the token-set refresh signature, and the nested MCP tool-call result.
Upstream's prewarm MCP tests now expect the `Result` that the patch's `mcp_runtime_for_step` returns.

`core-test-unused-import` drops its `scenarios` hunk: upstream now uses `ReasoningEffort` there.
It still removes the unused `body_json` import from `openai_file_mcp`.

`rust-toolchain-stable` shrinks to its `channel = "stable"` line:
upstream #55677 pins Rust 1.99.1 and carries the Rust 1.99 compatibility and snapshot hunks itself.
The `rust-overlay` flake input moves to its 2026-10-23 revision, so Nix builds and the development shell select Rust 1.99.1.

`tui-reasoning-display` adds its `TuiReasoningDisplay` type next to upstream's new `QuickDial` preset type.

Upstream moved `v8` from 150.4.0 to 152.2.0.
The Nix overlay pins the `rusty-v8-v152.2.0` pointer-compression sandbox artifacts;
their hashes come from the per-target checksum manifests, each verified against upstream's `third_party/v8/rusty_v8_152_2_0_release_manifests.sha256`.
The CI and release workflows resolve the version from the staged source and need no change.
crossterm stays at `ed1cdab`, so `crossterm-split-escape` is unchanged.
No packaged helper binary was added or removed.

`age` and `i18n-embed-fl` moved to releases that no longer depend on `proc-macro-error2`,
so the 0.157.0 future-compatibility waiver is removed from the temporary workarounds.

## Verification

- All twelve enabled patches apply cumulatively to a fresh `rust-v0.164.0` checkout with both `git apply` and Nix's `patch -p2`;
  both trees match the rebased chain exactly.
- `source_hash` comes from prefetching the upstream archive; `cargo_hash` from building the vendor derivation.
- `cargo check --all-targets` on x86_64-linux with Rust 1.99.1 passes without errors or warnings
  for the nine tested crates plus `codex-cli`, `codex-code-mode-host`, `codex-responses-api-proxy`, and `codex-thread-manager-sample`.
- Regenerating the app-server schema fixtures from the cumulative patched source leaves the carried JSON and TypeScript schema files unchanged;
  only the two compressed exports change.
- The nine-crate unit sweep, with CI's 16 MiB `RUST_MIN_STACK`, runs 10,472 tests: 10,471 pass; six upstream ignored tests remain skipped.
  The one failure is upstream's `pets::tests::kitty_local_file_pet_image_uses_file_reference_without_inline_payload`,
  which depends on the length of `TMPDIR`:
  the output base64-encodes the temporary file path, and the test forbids `cG5n`, the base64 of `png`.
  It fails under the Nix development shell's `/tmp/nix-shell.*` and passes with `TMPDIR=/tmp`, as on CI.
  No patch touches `tui/src/pets/`.
- The V8 sandbox linkage test passes with the pinned 152.2.0 pointer-compression sandbox artifacts.
- All 21 selected account-rotation, login-server, and blackholed-WebSocket integration scenarios pass.
